## ✅ What "Exit N" means
- "Exit N" is the process exit code returned by the script that ran. It's the integer value the process passed to the OS on termination (proc.returncode in Python).
- Common meanings:
  - `Exit 0` → success (no error).
  - `Exit 1` → general failure / unhandled exception (common when tests or scripts raise an error).
  - `Exit 127` → command not found (shell-level error).
  - Negative values (e.g. `Exit -9`) on Unix-like systems mean the process was terminated by a signal — `-9` means SIGKILL. On Windows negative return codes are uncommon but still possible from some programs.

## 🔎 How it applies to your logs
- Your current test_run.log shows:
  - `=== Exit 0 for case_1.py ===` etc. — all three tests finished successfully (Exit 0).
- Earlier failures produced `Exit 1` because imports were missing (ModuleNotFoundError) — that’s a standard non-zero exit code indicating an error.

## 🛠 How to debug non-zero exit codes
- Look at test_run.log (first lines contain tracebacks) — they tell you why a test exited non‑zero.
- Reproduce a failing test interactively (in your .venv) to see full traceback:
  - Linux/macOS:
    ```bash
    .venv/bin/python tests/case_1.py
    ```
  - Windows PowerShell:
    ```powershell
    .venv\Scripts\python tests\case_1.py
    ```
- Check the shell’s last exit code:
  - Linux/macOS: `echo $?`
  - Windows cmd: `echo %ERRORLEVEL%` / PowerShell: `$LASTEXITCODE`

## 📌 Quick reference
- Exit 0 = success
- Exit non-zero (like 1) = error / exception
- Exit negative on Unix-like = terminated by signal (map number to signal with `kill -l`)

If you saw "Exit -" (a literal dash) anywhere, that usually means the logger didn’t capture the numeric exit value — let me know where you saw `Exit -` exactly and I’ll track down the code path that produced it and fix it (likely a small logging bug).
